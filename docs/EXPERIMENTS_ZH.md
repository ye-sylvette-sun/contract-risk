# 预测实验 · 说明（中文）

配套文档：[数据集说明](DATASET_ZH.md)。

---

## 1. 我们在问什么

数据集告诉我们，哪些条款**事实上**被法院拿去解释过。实验反过来问：

> 给模型一份合同和它的全部条款，但**不告诉它答案**，它能不能自己指出哪几条会成为法庭上被攻击的目标？

难点在于比例。一份合同里被法院争过的条款通常只有个位数，其余几十上百条都没人碰过——整个评估集里 positive 只占 **2.1%**。所以这是一道"大海捞针"的题，模型很容易靠"多标一些"来刷成绩，评分时必须防住这一点（见第 5 节）。

---

## 2. 每次调用，模型拿到什么

**一份合同 = 一次调用**，一次把这份合同的所有条款判完。不切成小批，因为第 2 类风险问的是"这一条和别的条款有没有冲突"，把合同切开就等于把问题变简单了。

每次调用的输入包含四块：

**① 判断标准。**两大类风险的定义（和数据集用的是同一套：第 1 类看条款本身的文字，第 2 类看它和合同其余部分的关系），外加几条校准要求：不要因为条款重要就给高分；给第 1 类打高分必须能**点出**是哪个词有歧义；给第 2 类打高分必须能**点名**是和哪一条冲突。

**② 三个示范例子**，每种 risk category 一个。每个例子是同一份合同里的**一对**条款：

- 一个法院**真的解释过**的条款，**外加判决书里讨论它的那段原文**——让模型看到当时双方到底在争什么、法官觉得哪里不清楚；
- 同一份合同里**没被解释过**的一条，标为"风险较低"。

每个例子还会说明那份合同的实际比例（如"这份合同 3 条被解释过、95 条没有"），让模型知道该期待什么样的基数——但明确说这是**参考基数，不是要凑的指标**。

**③ 待判合同的全文。**

**④ 要判断的条款清单**，每条都是从合同里逐字摘出来的原文。这里有个关键处理：条款的编号一律换成 **`c001`、`c002`…** 这样的匿名编号，**按它们在合同里出现的先后排序**。

> 数据集里条款本来的编号是 `pos1`、`neg7` 这种——`pos` 开头的就是答案。直接给模型等于把答案写在每扇门上，而且会让所有正例都挤在清单开头。换成按出现顺序排的匿名编号，既不泄露答案，也让每一条都挨着它的邻居，这正是判断第 2 类风险所需要的。答案收回来之后，程序再把匿名编号翻译回原编号。

---

## 3. 模型要交回什么

对**每一条**条款，交回四样东西：

| 字段 | 内容 |
|---|---|
| `prob_cat1` | 这一条带第 1 类风险（条款自身文字有毛病）的概率，0–1，两位小数 |
| `prob_cat2` | 这一条带第 2 类风险（和合同其余部分有冲突）的概率，0–1，两位小数 |
| `reasoning_cat1` | 两句话，**只**评这一条自己的措辞 |
| `reasoning_cat2` | 两句话，**只**评它和整份合同的关系，并**点名它去核对过的是哪一条** |

两个概率是**各自独立**的，不要求加起来等于 1——一个条款可以两类都不沾、只沾一类，或者两类都沾。

要求写到小数点后两位（0.03、0.17、0.62），不许四舍五入到 0.05 或 0.1，因为我们真正在意的是条款**之间**的高低排序，而不是某一条的绝对分值。

如果模型漏判了一部分条款，程序会**追问一次**（把它自己的答案回放给它，列出漏掉的编号让它补齐），而不是把漏掉的直接当成"低风险"——否则测的就是我们的流程，不是模型。

---

## 4. 两种跑法

同一个问题、**同样的措辞**，只有材料递到模型手上的**方式**不同：

| | 一次性调用 | agent 模式 |
|---|---|---|
| 形式 | 一次 API 调用判完一份合同 | 一个 Claude Code 会话判完一份合同 |
| 合同 | 直接写在提问里 | 工作目录里的一个文件 |
| 怎么读 | 按给定顺序，读一遍 | 自己决定：读、回头再读、搜关键词 |
| 怎么交答案 | 一次性输出 | 自己写成文件，可以分批写 |

设这两种跑法，是想知道**"能回头翻合同"值不值钱**——第 2 类风险本质上是在一份几十万字的文件里做检索，一次性调用只能凭一遍阅读作答。

评估用 **64 份合同、6,461 个条款**（其中 134 个 positive）。另外 3 份合同永久留作示范例子，不参与评估，保证模型没在自己被考的题上学过。

---

## 5. 怎么评分

概率 ≥ 某个阈值就算模型"标出了"这一条。我们看三个数：

- **精确率**：模型标出来的条款里，有多少真的被法院争过；
- **召回率**：真的被争过的条款里，模型找出来了多少；
- **标记比例**：模型一共标了多少条。

第三个数是防作弊用的。在 2% 的基数下，一个把整份合同标出三分之一的模型也能有好看的召回率，所以召回率必须和标记比例一起看。

另外还看两个不依赖阈值的**排序**指标（AUC）：不管阈值定在哪，模型有没有把真正被争过的条款排在前面。在 2% 这么低的基数下，**PR-AUC 是最该看的那个数**。

---

## 6. 结果

两边都判完了全部 64 份合同、6,461 个条款，没有漏判，所以是同题同条件的对比。
完整分析见 [REPORT.md](REPORT.md)。

| 面板 | | ROC-AUC | PR-AUC | 精确率@0.5 | 召回率@0.5 | 标记比例 |
|---|---|---:|---:|---:|---:|---:|
| 有风险 vs 无 | 一次性调用 | 0.869 | 0.312 | 0.21 | 0.46 | 4.6% |
| 有风险 vs 无 | **agent 模式** | **0.891** | **0.385** | **0.25** | **0.54** | 4.5% |
| 第 1 类（自身缺陷） | 一次性调用 | 0.863 | 0.303 | 0.25 | 0.40 | 3.0% |
| 第 1 类（自身缺陷） | **agent 模式** | **0.890** | **0.358** | **0.31** | **0.48** | 3.0% |
| 第 2 类（条款冲突） | 一次性调用 | **0.958** | 0.139 | 0.04 | 0.42 | 2.1% |
| 第 2 类（条款冲突） | agent 模式 | 0.942 | **0.220** | 0.04 | **0.58** | 2.5% |

在 2.1% 的基数下**该看 PR-AUC**：ROC-AUC 被 6,327 个容易的负样本抬高了。三个面板的
PR-AUC agent 模式都领先，而且标记比例还更低一点（4.5% vs 4.6%）——多出来的召回不是
靠多标，是同样多的标记里选得更准。

**要达到某个召回率各自要读多少**（有风险 vs 无面板）：

| 召回率 | | 阈值 | 精确率 | 标记比例 |
|---:|---|---:|---:|---:|
| 70% | 一次性调用 | 0.37 | 0.088 | 16.7% |
| 70% | **agent 模式** | 0.42 | **0.122** | **12.1%** |
| 80% | 一次性调用 | 0.31 | 0.059 | 28.9% |
| 80% | **agent 模式** | 0.35 | **0.077** | **21.9%** |
| 90% | 一次性调用 | 0.25 | 0.047 | **39.9%** |
| 90% | agent 模式 | 0.27 | 0.046 | 41.7% |

要抓住五分之四被争过的条款，agent 模式只要读 22% 的合同，一次性调用要读 29%——少读
四分之一。到 90% 时两边都退化到要读四成合同，谁都不好用了。

**两边共同的弱点**：对第 2 类风险，两者都能把它排在前面（排序指标很高），但给出的
**概率数值都不可信**（精确率都只有 0.04，且只有 12 个正样本）。这一类目前只能当排序
用，不能当作绝对概率读。

**每个方案只跑了一次**：两边都没有设温度或随机种子，重跑不会得到同样的数字。跑与跑之间
的波动**没有测量**，上面这些差距也不能保证超过这个波动。详见 [REPORT.md](REPORT.md)
第 5 节。
