# 风险检测 · 结果（中文）

每份合同一个隔离的 Claude Code session,给它合同全文,问它哪些条款会被法院拿去
解释,以及它说出的缺陷是不是法院实际解释的那一个。

## 运行配置

```
模型        claude-opus-5, effort high, 100 轮上限
运行环境    每份合同一个容器, contract-risk-judge:0.2.139
            sha256:b5f50d7dc71f6eae1ce623fbbcad0853e927ce6c564ae44d9ff53015f1bb1fec
鉴权        CLAUDE_CODE_OAUTH_TOKEN(订阅),从不使用 API key
评测集      84 份合同, 9,890 个条款, 3 份 example 合同持出
gold        163 个被解释条款, 225 个记录在案的缺陷
成本        $169.47(按 API 等价费率), 0 次失败
```

alignment 判官是 `gpt-5.6-sol`(high effort)—— 与被评模型不同家族,且从未看到
agent 的推理过程。

## 1. 排序能力

三个 one-vs-rest 任务。条款的分数取该类型的概率,`risky` 取两者较大值。

| | positive 数 | ROC-AUC | recall 天花板 |
|---|---|---|---|
| risky vs not | 163 (1.6%) | **0.868** | 0.99 |
| risk type 1 — 条款自身缺陷 | 120 (1.2%) | **0.770** | 0.72 |
| risk type 2 — 关系型缺陷 | 68 (0.7%) | **0.690** | 0.59 |
| 仅按条款长度排序 | | **0.691** | |

recall 天花板是阈值取 0.01 时的 recall:gold 条款中拿到过该类型任意概率条目的
比例。任何阈值都无法超过它。

**risk type 2 没有超过条款长度基线。** 0.690 对 0.691。模型相对长度基线的全部
增益都在 type 1 和 risky/not 这个二元问题上;在关系型这一半上没有可测量的贡献。

图:`output/figures/risk_detect_agent_threshold_curves.png`

## 2. 没有可用的工作点

| 阈值 | precision | recall | 标记数 |
|---|---|---|---|
| 0.3 | 0.08 | 0.66 | 1,341 (13.6%) |
| 0.5 | 0.30 | 0.16 | 88 (0.9%) |

precision 与 recall 在 t ≈ 0.45 相交,两者都在 0.25 附近。在 1.6% 的 prevalence
下这远高于随机,但仍远达不到可以实际投入使用的水平。这次运行证明的是排序能力,
不是一个可用的检测器。

0.99 这个 risky 天花板必须和产生它的标记率一起读:模型在 **68%** 的条款上都写了
至少一条 issue。不是几乎每个被解释的条款都被识别出来了,而是几乎每个条款都拿到
了点什么。

## 3. 是否说对了缺陷

排序任务无法判断条款是不是因为法院的那个理由被标记的。alignment 检查单独回答
这件事:agent 说出的每一条 issue,是不是该条款已记录缺陷中的某一个?

```
209 条 issue, 覆盖 161 个条款
 69 条命中  =  33.0%
 69 个不重复的 gold 缺陷被匹配, 语料共 225 个
```

**必须对照控制组来读这个数。** 把每条 issue 重新配对到**同一案件中另一个条款**的
缺陷上 —— 故意配错,但合同相同、争议相同、法律语汇相同 —— 判官仍然给出 28 次匹配:

| | 主实验 | 控制(同案) | 比值 |
|---|---|---|---|
| 全部 issue | 33.0% | 14.2% | 2.3× |
| gold 1.1 — 词汇歧义 | 24.3% | 2.9% | **8.4×** |
| gold 2.2 — 整体一致性 | 35.2% | 26.4% | **1.3×** |

**在 1.1 上这个测量是可信的;在 2.2 上不可信。** 关系型缺陷的描述形如「这一条要
和那一条一起读」,而控制组的假配对往往**就是**同一份文书里的另一条,两边的描述
几乎可以互换。判官分不开它们。

这与排序任务经由完全独立的路径得到同一个结论:在 risk type 2 上,AUC 等于长度
基线。**两个不共用任何机制的测量,一致指向关系型这一半在当前设置下没有可用信号。**

**risk type 不参与 alignment 判定。** 判官看不到任何一方的类型,候选也不按类型
过滤 —— 因为数据集的类型标签来自案件的 Westlaw key,而不是来自 opinion 段落。
类型一致性单独报告:69 个匹配对中 52 个(75.4%)粗类型一致,其余 17 个说的是同
一个缺陷但归了不同的类型。

图:`output/figures/issue_alignment_threshold_curves.png`

## 4. 两个测量放在一起说明了什么

```
risky recall 天花板   0.99      几乎每个被解释的条款都拿到了条目
alignment            33.0%     其中约三分之一说对了缺陷
```

模型擅长判断**该看哪里**,在说清**哪里不对**上弱得多。逐条读未命中的案例可以确认
这一点:它说出的缺陷通常是正确条款上真实的起草问题 —— 未定义的术语、缺失的补救
期限、指向日期写错的信函的交叉引用 —— 只是并非最终变成诉讼的那一个。

判官并没有过严。它的打分实际上是二元的:209 条 issue 中,**没有任何一条落在 0.01
到 0.49 之间**,所以降低阈值不改变任何结果。140 条未命中里,有 15 条引用了同样
出现在某个已记录缺陷中的文字,逐条读下来其中约 4 条确实有争议。即使把这 15 条
全部改判为命中,33.0% 变成 39.7%,控制组从 14.2% 变成 18.8% —— 比值从 2.3× 降到
2.1×,也就是说放宽标准换来分数、损失判别力。

## 5. 哪些结论不成立

- **没有噪声底。** 这里每一个数字都是单次观测。同一 prompt 从未在这个数据集上跑
  过两遍,因此任何配置之间的差异都不能称为真实差异。
- **type-2 的结论是关于这套设置的,不是关于这个任务的。** AUC 0.690 对 0.691 说明
  这条流水线没有提取到任何信息;它没有说关系型缺陷不可检测。
- **recall 是下界。** step 2 只能记录它在 opinion 中定位得到的内容,语料中有 45 个
  issue 需要语料并不持有的文书。法院解释过但数据集从未记录的缺陷,会被算作 agent
  的未命中。
- **alignment 判官的绝对命中率单独没有意义** —— 有意义的只是它与控制组的差距,而在
  2.2 上这个差距很小。
- **75.4% 的类型一致率是与数据集标注约定的一致率,不是准确率。** 数据集里每个缺陷
  的类型来自案件的 Westlaw key,那是一个案件级的事实。
